# 개발 로드맵

## 1. 로드맵 목적

이 문서는 헷갈림 퀴즈 프로젝트를 어떤 순서로 개발할지 정리합니다.

초기 버전은 기능을 한 번에 모두 구현하지 않고, 화면과 API, DB를 단계적으로 연결하는 방식으로 진행합니다.

## 2. 개발 단계 요약

| 단계 | 이름 | 목표 |
|---|---|---|
| 1단계 | 프로젝트 초기 세팅 | 프론트엔드, 백엔드, DB 실행 기반 구성 |
| 2단계 | 프론트엔드 정적 화면 구현 | 화면 설계서 기준으로 기본 UI 구성 |
| 3단계 | 백엔드 기본 구조 구현 | Spring Boot API 서버 기본 구조 구성 |
| 4단계 | DB 연결 및 엔티티 구현 | PostgreSQL 연결과 테이블 구조 구현 |
| 5단계 | 초기 문제 데이터 준비 | 카테고리별 퀴즈 문제 데이터 구성 |
| 6단계 | Google 로그인 연동 | 소셜 로그인과 사용자 저장 구현 |
| 7단계 | 퀴즈 조회/풀이 구현 | 카테고리 선택과 문제 풀이 흐름 구현 |
| 8단계 | 결과 저장/랭킹 구현 | 퀴즈 결과 저장과 랭킹 조회 구현 |
| 9단계 | API 단독 테스트 | 프론트엔드 연결 전 API 동작 검증 |
| 10단계 | 문서 정리 및 시연 준비 | README, 실행 방법, 트러블슈팅 정리 |

## 3. 단계별 계획

### 1단계 프로젝트 초기 세팅

| 항목 | 내용 |
|---|---|
| 목표 | 프로젝트의 기본 폴더 구조와 실행 환경을 구성한다. |
| 작업 내용 | React + TypeScript + Vite 프론트엔드 생성, Spring Boot 백엔드 생성, Docker Compose DB 설정 |
| 완료 기준 | 프론트엔드 개발 서버, 백엔드 서버, PostgreSQL 컨테이너를 각각 실행할 수 있다. |
| 주의점 | 처음부터 기능을 넣지 않고, 실행 가능한 빈 프로젝트를 먼저 만든다. |

### 2단계 프론트엔드 정적 화면 구현

| 항목 | 내용 |
|---|---|
| 목표 | API 연결 없이 화면 설계서 기준의 기본 화면을 만든다. |
| 작업 내용 | 홈 화면, 로그인 화면, 카테고리 선택 화면, 퀴즈 풀이 화면, 결과 화면, 랭킹 화면 구현 |
| 완료 기준 | 사용자가 화면 사이를 이동할 수 있고, 더미 데이터로 화면을 확인할 수 있다. |
| 주의점 | 이 단계에서는 실제 로그인, DB, API 연결을 하지 않는다. |

### 3단계 백엔드 기본 구조 구현

| 항목 | 내용 |
|---|---|
| 목표 | API 서버의 기본 계층 구조를 만든다. |
| 작업 내용 | Controller, Service, Repository, DTO 패키지 구성, 공통 에러 응답 구조 작성 |
| 완료 기준 | 간단한 헬스 체크 또는 테스트 API가 정상 응답한다. |
| 주의점 | API 명세서의 URL 구조를 기준으로 패키지와 클래스 이름을 정리한다. |

### 4단계 DB 연결 및 엔티티 구현

| 항목 | 내용 |
|---|---|
| 목표 | PostgreSQL과 백엔드를 연결하고 DB 설계서 기준의 엔티티를 구현한다. |
| 작업 내용 | Docker Compose로 PostgreSQL 실행, DB 접속 설정, users, quiz_questions, quiz_choices, quiz_results, quiz_answers 엔티티 작성 |
| 완료 기준 | 백엔드가 DB에 연결되고, 기본 테이블 생성 또는 마이그레이션이 가능하다. |
| 주의점 | 민감한 DB 설정값은 환경 변수 또는 별도 설정 파일로 관리한다. |

### 5단계 초기 문제 데이터 준비

| 항목 | 내용 |
|---|---|
| 목표 | 퀴즈 문제 조회 기능을 검증할 수 있는 초기 데이터를 준비한다. |
| 작업 내용 | 카테고리별 문제 10개 이상 작성, 선택지 4개와 정답 정보 작성, 초기 데이터 삽입 방식 결정 |
| 완료 기준 | 각 카테고리에서 퀴즈 문제 10개를 조회할 수 있다. |
| 주의점 | 초기 버전에서는 OpenAI 문제 생성 없이 직접 준비한 문제 데이터를 사용한다. |

### 6단계 Google 로그인 연동

| 항목 | 내용 |
|---|---|
| 목표 | Google OAuth 기반 로그인과 사용자 저장 흐름을 구현한다. |
| 작업 내용 | Google OAuth Client 설정, Spring Security OAuth2 설정, 로그인 성공 후 사용자 저장, `/api/me` 구현, CORS 및 세션 쿠키 설정 확인 |
| 완료 기준 | Google 계정으로 로그인할 수 있고, 로그인 사용자의 정보가 DB에 저장된다. |
| 주의점 | Client ID와 Secret은 코드에 직접 작성하지 않는다. 프론트엔드와 백엔드의 포트가 다르므로 세션 기반 인증 요청이 정상 동작하는지 확인한다. |

### 7단계 퀴즈 조회/풀이 구현

| 항목 | 내용 |
|---|---|
| 목표 | 사용자가 카테고리를 선택하고 10개의 문제를 풀 수 있게 한다. |
| 작업 내용 | 카테고리 API 구현, 문제 조회 API 구현, 프론트엔드 퀴즈 풀이 상태 관리 구현 |
| 완료 기준 | 로그인 사용자가 카테고리를 선택하고 10개의 문제를 풀 수 있다. |
| 주의점 | 문제 조회 응답에는 정답 정보를 포함하지 않는다. |

### 8단계 결과 저장/랭킹 구현

| 항목 | 내용 |
|---|---|
| 목표 | 퀴즈 결과를 저장하고 카테고리별 랭킹을 조회할 수 있게 한다. |
| 작업 내용 | 결과 제출 API 구현, 정답 검증 로직 구현, quiz_results/quiz_answers 저장, 랭킹 API 구현 |
| 완료 기준 | 퀴즈 제출 후 결과 화면이 표시되고, 랭킹 화면에서 기록을 확인할 수 있다. |
| 주의점 | 정답 검증은 클라이언트가 아니라 서버에서 처리한다. |

### 9단계 API 단독 테스트

| 항목 | 내용 |
|---|---|
| 목표 | 프론트엔드 연결 전에 백엔드 API가 명세대로 동작하는지 확인한다. |
| 작업 내용 | `/api/me`, `/api/categories`, `/api/quiz/questions`, `/api/quiz/results`, `/api/rankings` 동작 확인, 주요 에러 케이스 확인 |
| 완료 기준 | 주요 API가 정상 응답하고, 백엔드 테스트가 통과한다. |
| 주의점 | 인증이 필요한 API와 인증이 필요 없는 API를 구분해서 테스트한다. |

### 10단계 문서 정리 및 시연 준비

| 항목 | 내용 |
|---|---|
| 목표 | 포트폴리오 제출과 시연에 필요한 문서를 정리한다. |
| 작업 내용 | README 작성, 실행 방법 정리, 환경 변수 예시 작성, 주요 기능 캡처, 트러블슈팅 정리 |
| 완료 기준 | 처음 보는 사람이 README를 보고 프로젝트를 실행하고 주요 기능을 이해할 수 있다. |
| 주의점 | 구현한 기능과 문서 내용이 다르지 않도록 마지막에 다시 검토한다. |

## 4. 우선 개발 순서

초기 개발은 다음 순서로 진행합니다.

```text
프론트엔드 정적 화면
  ↓
백엔드 API 기본 구조
  ↓
DB 연결
  ↓
초기 문제 데이터 준비
  ↓
Google 로그인
  ↓
퀴즈 문제 조회
  ↓
결과 저장
  ↓
랭킹 조회
  ↓
README 정리
```

## 5. 구현 보류 항목

초기 버전에서는 다음 작업을 진행하지 않습니다.

| 항목 | 보류 이유 |
|---|---|
| 관리자 페이지 | 초기 버전은 사용자 퀴즈 플레이 흐름에 집중한다. |
| OpenAI 문제 생성 | 관리자 검토 흐름이 없으므로 초기 버전에서는 제외한다. |
| 실시간 대전 | 실시간 통신과 매칭 로직이 필요해 범위가 커진다. |
| 여러 소셜 로그인 | Google 로그인 하나로 인증 흐름을 먼저 완성한다. |
| 배포 자동화 | 로컬 실행과 포트폴리오 시연 안정성을 먼저 확보한다. |
