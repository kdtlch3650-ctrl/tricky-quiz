# 요구사항 정의서

## 1. 기능 범위

초기 버전은 사용자가 Google 계정으로 로그인한 뒤 카테고리를 선택하고, 10개의 퀴즈를 풀고, 결과를 저장한 뒤 랭킹을 확인하는 흐름을 구현합니다.

초기 카테고리는 다음 4개로 구성합니다.

| 카테고리 | 설명 |
|---|---|
| 상식 | 일상에서 접하기 쉬운 일반 상식 문제 |
| IT | 개발, 컴퓨터, 인터넷 관련 상식 문제 |
| 과학 | 기초 과학과 생활 속 과학 문제 |
| 생활 | 생활 정보, 문화, 상황 판단 관련 문제 |

랭킹은 점수가 높은 순으로 정렬하고, 점수가 같을 경우 풀이 시간이 짧은 사용자를 우선합니다.

## 2. 사용자 역할

| 역할 | 설명 | 가능한 행동 |
|---|---|---|
| 일반 사용자 | 서비스에 로그인하고 퀴즈를 플레이하는 사용자 | Google 로그인, 카테고리 선택, 퀴즈 풀이, 결과 확인, 랭킹 조회 |
| 리뷰어 | 포트폴리오를 확인하는 사람 | 소셜 로그인 흐름, API 통신, DB 저장 및 조회, Docker 실행 구조, 문서화 상태 확인 |

## 4. 기능 요구사항 상세

### REQ-001 Google 소셜 로그인

- 구분: 인증
- 우선순위: 필수
- 설명: 사용자는 Google 계정으로 로그인할 수 있다.
- 입력/조건:
  - Google 계정
- 완료 기준:
  - 로그인 후 사용자 식별이 가능하다.
  - 로그인 상태에서 퀴즈 플레이가 가능하다.
- 비고: OAuth 기반 인증 흐름을 사용한다.

### REQ-002 사용자 정보 저장

- 구분: 사용자
- 우선순위: 필수
- 설명: 최초 로그인한 사용자의 기본 정보를 DB에 저장한다.
- 입력/조건:
  - Google 계정 식별값
  - 이메일
  - 닉네임
- 완료 기준:
  - 최초 로그인 시 사용자 정보가 생성된다.
  - 재로그인 시 기존 사용자 정보가 중복 생성되지 않는다.
- 비고: 사용자 ID를 기준으로 퀴즈 결과와 랭킹 데이터를 연결한다.

### REQ-003 퀴즈 카테고리 조회

- 구분: 퀴즈
- 우선순위: 필수
- 설명: 사용자는 퀴즈 시작 전에 카테고리를 선택할 수 있다.
- 입력/조건:
  - 상식
  - IT
  - 과학
  - 생활
- 완료 기준:
  - 화면에 카테고리 목록이 표시된다.
  - 사용자는 하나의 카테고리를 선택할 수 있다.
- 비고: 초기 버전에서는 4개 카테고리만 제공한다.

### REQ-004 퀴즈 문제 조회

- 구분: 퀴즈
- 우선순위: 필수
- 설명: 선택한 카테고리에 맞는 퀴즈 문제를 제공한다.
- 입력/조건:
  - 선택한 카테고리
- 완료 기준:
  - 선택한 카테고리에 맞는 10개의 문제가 제공된다.
  - 각 문제는 4개의 선택지를 가진다.
  - 정답은 제출 전까지 노출되지 않는다.
- 비고: 초기 문제는 미리 준비된 문제 데이터를 사용한다.

### REQ-005 퀴즈 풀이

- 구분: 퀴즈
- 우선순위: 필수
- 설명: 사용자는 각 문제마다 하나의 선택지를 고를 수 있다.
- 입력/조건:
  - 10개의 문제
  - 각 문제의 선택지
- 완료 기준:
  - 사용자는 모든 문제에 답을 선택할 수 있다.
  - 답을 선택하지 않은 문제가 있으면 제출 전 안내한다.
- 비고: 한 문제에는 하나의 답만 선택할 수 있다.

### REQ-006 정답 확인

- 구분: 퀴즈
- 우선순위: 필수
- 설명: 사용자는 퀴즈 제출 후 정답 여부를 확인할 수 있다.
- 입력/조건:
  - 사용자가 제출한 답안
- 완료 기준:
  - 사용자 선택 답이 표시된다.
  - 정답이 표시된다.
  - 문제별 정답 여부가 표시된다.
  - 전체 점수가 표시된다.
- 비고: 각 문제에는 간단한 해설을 포함할 수 있다.

### REQ-007 퀴즈 결과 저장

- 구분: 결과
- 우선순위: 필수
- 설명: 사용자의 퀴즈 결과를 DB에 저장한다.
- 입력/조건:
  - 사용자 ID
  - 카테고리
  - 점수
  - 전체 문제 수
  - 풀이 시간
  - 플레이 일시
- 완료 기준:
  - 퀴즈 제출 후 결과가 DB에 저장된다.
  - 저장된 결과는 랭킹 조회에 사용된다.
- 비고: 같은 사용자가 여러 번 플레이할 수 있다.

### REQ-008 랭킹 조회

- 구분: 랭킹
- 우선순위: 필수
- 설명: 사용자는 다른 사용자와 점수를 비교할 수 있다.
- 입력/조건:
  - 카테고리
- 완료 기준:
  - 랭킹은 점수 높은 순으로 표시된다.
  - 점수가 같으면 풀이 시간이 짧은 사용자가 먼저 표시된다.
  - 점수와 풀이 시간이 같으면 먼저 제출한 사용자가 먼저 표시된다.
- 비고: 초기 버전에서는 카테고리별 랭킹을 제공한다.

## 5. 비기능 요구사항

| ID | 구분 | 요구사항 | 설명 | 완료 기준 |
|---|---|---|---|---|
| NFR-001 | 사용성 | 직관적인 퀴즈 흐름 | 사용자는 복잡한 설명 없이 로그인, 카테고리 선택, 퀴즈 풀이, 결과 확인 흐름을 이해할 수 있어야 한다. | 주요 버튼과 이동 흐름이 명확하다. |
| NFR-002 | 응답 속도 | 기본 조회 응답성 | 퀴즈 문제 조회와 랭킹 조회는 사용자가 기다림을 크게 느끼지 않도록 처리한다. | 로컬 실행 기준으로 주요 조회가 지연 없이 동작한다. |
| NFR-003 | 데이터 안정성 | 결과 저장 보장 | 퀴즈 제출 후 결과가 DB에 저장되어야 하며, 같은 사용자가 여러 번 플레이할 수 있어야 한다. | 제출한 결과가 DB에 저장되고 다시 조회할 수 있다. |
| NFR-004 | 보안 | 로그인 기반 사용자 구분 | 로그인하지 않은 사용자는 퀴즈 결과 저장 기능을 사용할 수 없다. | 로그인 사용자만 결과 저장 API를 사용할 수 있다. |
| NFR-005 | 설정 관리 | 민감 정보 환경 변수 관리 | DB 정보, OAuth 설정값 등 민감한 값은 코드에 직접 작성하지 않는다. | 환경 변수 또는 별도 설정 파일로 관리한다. |
| NFR-006 | 실행 환경 | Docker 기반 DB 실행 | 개발 환경에서 Docker Compose로 DB를 실행할 수 있어야 한다. | `docker compose up -d`로 DB가 실행되고 백엔드가 연결된다. |
| NFR-007 | 실행 구조 | 프론트엔드/백엔드 분리 실행 | 프론트엔드와 백엔드는 분리된 서버로 실행한다. | 프론트엔드와 백엔드가 API로 통신한다. |
| NFR-008 | 문서화 | README 실행 문서 제공 | 프로젝트 소개, 실행 방법, 환경 변수, 주요 기능을 README에 정리한다. | 처음 보는 사람이 README를 보고 프로젝트를 실행할 수 있다. |
| NFR-009 | 시연 안정성 | 로컬 실행 안정성 | 초기 버전은 대용량 트래픽보다 로컬 실행과 포트폴리오 시연 안정성을 우선한다. | README 기준으로 로컬 실행이 가능하다. |

## 6. 제외 요구사항

| ID | 제외 기능 | 제외 이유 |
|---|---|---|
| EXC-001 | 관리자 페이지 | 초기 버전에서는 사용자 퀴즈 플레이 흐름에 집중한다. |
| EXC-002 | 결제 기능 | 프로젝트 목적과 직접 관련이 없고 구현 범위가 커진다. |
| EXC-003 | 실시간 대전 | 실시간 통신과 매칭 로직이 필요해 초기 범위를 벗어난다. |
| EXC-004 | 모바일 앱 | 웹 서비스 구현을 우선한다. |
| EXC-005 | 여러 소셜 로그인 동시 지원 | Google 로그인 하나로 인증 흐름을 먼저 완성한다. |
| EXC-006 | OpenAI API를 활용한 문제 생성 | 관리자 페이지가 없는 초기 버전에서는 기능 흐름이 애매하므로 제외한다. |
| EXC-007 | OpenAI 생성 문제 자동 출제 | 문제 품질 검토 흐름이 필요하므로 초기 버전에서는 제외한다. |
| EXC-008 | 복잡한 통계 분석 기능 | 결과 저장과 랭킹 조회를 우선한다. |
