# 추가로 고민해 볼 항목

이 문서는 작업하면서 계속 선택지가 바뀌었던 것들 중, 아직 최종 확정 전에 다시 볼 항목만 남겨둔 메모입니다.

## 1. 퀴즈 진행 UX

### 고민

- 답을 한 번 누르면 바로 다음 문제로 넘어가게 할지
- 같은 선택지를 한 번 더 눌러 다음 문제로 넘어가게 할지
- 하단에 별도 `다음` 버튼을 둘지

### 왜 고민했는지

- O/X 퀴즈는 한 문제당 조작이 너무 많으면 금방 피로해진다.
- 반대로 너무 자동으로 넘어가면 사용자가 답을 바꿀 시간이 없다.
- 이 프로젝트는 `헷갈리는 문제`가 핵심이라서, 답을 누른 뒤 한 번 더 확인하는 흐름이 필요했다.

### 해결 방법

- 현재 방식처럼 `같은 선택지를 한 번 더 누르면 다음 문제로 이동`을 기본으로 둔다.
- 마지막 문제에서는 같은 동작이 `제출`로 이어지게 한다.
- 모바일에서도 조작 횟수가 늘어나지 않아서 가장 균형이 좋다.

## 2. 로그인 / 로그아웃 노출 방식

### 고민

- 로그아웃 버튼을 항상 보이게 할지
- 닉네임 클릭 후 메뉴로 열지
- 모바일에서 같은 동작을 그대로 유지할지

### 왜 고민했는지

- 로그아웃은 자주 쓰는 기능은 아니지만, 막상 찾기 쉬워야 한다.
- 항상 보이면 편하지만 헤더가 복잡해지고, 숨기면 깔끔하지만 발견성이 떨어진다.
- 모바일에서도 같은 규칙이 유지돼야 사용자가 덜 헷갈린다.

### 해결 방법

- 닉네임을 눌렀을 때만 로그아웃 메뉴를 열도록 유지한다.
- 메뉴 바깥을 클릭하면 닫히게 한다.
- 모바일에서는 메뉴 폭을 `100%`로 맞춰서 터치하기 쉽게 둔다.

## 3. 모바일 카테고리 버튼 배치

### 고민

- 카테고리 버튼을 모바일에서 2열로 유지할지
- 아주 작은 화면에서만 1열로 바꿀지

### 왜 고민했는지

- 모바일에서 카드가 너무 크면 첫 화면에서 스크롤이 길어진다.
- 하지만 1열로만 두면 선택까지 너무 오래 내려가야 한다.
- 그래서 세로 공간을 줄이면서도 선택은 빨리 할 수 있는 2열이 더 적절했다.

### 해결 방법

- 모바일에서도 카테고리 버튼은 2열을 유지한다.
- 카드 높이와 패딩, 글자 크기를 줄여 세로 스크롤을 줄인다.
- 첫 화면에서 바로 카테고리를 선택할 수 있게 만드는 쪽이 더 낫다.

## 4. 문항 구성

### 고민

- O/X 형식을 유지할지
- 보기 3지선다로 다시 갈지
- 문항을 더 어렵게 할지, 더 직관적으로 할지

### 왜 고민했는지

- 처음엔 3지선다가 흔해서 익숙하지만, 트릭 퀴즈의 느낌은 덜했다.
- O/X는 짧고 직관적이라 문장 자체의 함정이 더 잘 드러난다.
- 이 프로젝트는 보기보다 문장 자체가 핵심이라 O/X가 더 맞았다.

### 해결 방법

- O/X 형식을 유지한다.
- 지금처럼 `문장 자체가 트릭인 문제`에 맞춘다.
- 3지선다로 바꾸면 보기가 다시 중심이 되어서, 현재 프로젝트 방향과는 덜 맞는다.

## 5. OAuth 설정

### 고민

- `launch.json`에 직접 넣는 방식으로 유지할지
- 별도 `.env` 파일 방식으로 바꿀지
- Google Cloud Console 설정 절차를 문서화할지

### 왜 고민했는지

- 처음에는 VS Code에서 바로 돌리는 편의성이 중요해서 `launch.json`이 가장 편했다.
- 그런데 설정이 IDE에 묶이기 때문에, 나중에 실행 방식이 바뀌면 재사용성이 떨어질 수 있다.
- Google OAuth는 `client id`, `client secret`, `redirect uri`가 함께 맞아야 해서, 어디에 무엇을 넣는지 헷갈리기 쉬웠다.
- 그래서 로컬 편의성, 보안, 이식성 사이에서 어떤 방식을 기본으로 둘지 고민이 필요했다.

### 해결 방법

- 현재는 `launch.json` 방식으로 유지한다.
- 로컬 실행 편의성이 좋고, VS Code에서 바로 관리하기 쉽다.
- 다만 실제 배포 단계로 가면 `.env` 또는 배포 환경변수로 옮기는 것이 더 좋다.
